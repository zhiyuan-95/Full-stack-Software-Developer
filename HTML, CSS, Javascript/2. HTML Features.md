# HTML5, the DOM, and XHTML

## HTML5 Features

HTML5 supports modern, interactive applications by providing:

- **Semantic page sections** for organizing content
- **Data-management capabilities**
- **Graphics and drawing tools**
- Native **video and audio**
- APIs that support application-like behavior
- Cross-browser and portable-device development
- More consistent experiences across platforms and devices

Together, these capabilities allow websites to offer experiences resembling desktop applications.

## Basic HTML5 Document Structure

```html
<!DOCTYPE html>
<html>
  <head>
    <title>Sample page</title>
  </head>
  <body>
    <p>Page content</p>
  </body>
</html>
```

### Main Components

- `<!DOCTYPE html>` declares the document type and tells the browser to use modern HTML rules. It is an instruction, not an HTML element, and belongs at the beginning of the document.
- `<html>` is the document’s **root element**. It contains every HTML element except the doctype declaration.
- `<head>` contains metadata and initialization resources, such as:
  - Page title
  - Scripts
  - Styles
  - Stylesheet links
  - Metadata
  - Browser-related information
- `<body>` contains the content displayed on the web page.

## Parsing and Media Types

A document delivered with the `text/html` media type is parsed according to **HTML rules**.

The declared content type matters because it determines how a browser processes the document:

```text
text/html       → HTML parser
application/xml → XML parser
```

## Document Object Model

After receiving an HTML document, the browser parses its markup and creates a **Document Object Model (DOM) tree**.

The DOM is an **in-memory, hierarchical representation** of the document. Its nodes can include:

- A document-type node
- Element nodes, such as headings and paragraphs
- Text nodes
- Comment nodes

For example:

```text
Document
├── DOCTYPE
└── html
    ├── head
    │   └── title
    │       └── "Sample page"
    └── body
        └── p
            └── "Page content"
```

Scripts can use the DOM to read, modify, add, or remove page content and elements.

## XML and XHTML

**XML** stands for **Extensible Markup Language**. An XML document normally begins with an XML declaration:

```xml
<?xml version="1.0" encoding="UTF-8"?>
```

When HTML is written and delivered using XML rules, it is commonly called **XHTML**. The document must be sent with an XML media type, such as `application/xml`, and is processed by an XML parser.

## HTML vs. XHTML Syntax

Both forms use essentially the same HTML elements and semantic tags, but their syntax rules differ.

| Rule | HTML | XHTML/XML |
|---|---|---|
| Element-name case | Generally case-insensitive | Must use the required case; XHTML uses lowercase |
| Closing tags | Some may be omitted | Every element must be properly closed |
| Attribute values | HTML parsing can tolerate some omissions | Every attribute must have a value |
| Quotation marks | Some values may be unquoted | Values must use single or double quotes |
| Error handling | Browsers often recover from malformed markup | An XML parser stops on a well-formedness error |
| Strictness | Forgiving | Rigorous |

Although browsers can recover from malformed HTML, developers should still write valid, consistently structured markup.

## Choosing Between HTML and XHTML

Use **HTML** for most conventional web pages because browsers handle it flexibly and recover from many markup errors.

Use **XHTML/XML syntax** when the application depends on XML processing, strict well-formedness, or tools such as **XSLT (Extensible Stylesheet Language Transformations)** to transform pages into other documents or resources.

## Key Takeaway

HTML5 provides semantic structure, media, graphics, data-management features, and APIs for cross-platform web applications. Browsers parse a document according to its media type and represent it internally as a DOM tree. HTML offers forgiving parsing, while XHTML follows strict XML rules and is most useful when XML-based processing is required.
