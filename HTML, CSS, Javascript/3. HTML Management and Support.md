# HTML5 Themes and Web-Application Features

## Compatibility and Conformance

HTML5 was designed to work with content created for **HTML4** and **XHTML1**, helping browsers remain compatible with existing web pages.

It separates conformance requirements for two groups:

- **User agents:** Browsers continue recognizing many elements and attributes from earlier specifications.
- **Authors:** Developers follow a simplified standard in which some older elements and attributes have been removed.

This distinction allows browsers to handle legacy content while encouraging developers to write modern HTML.

## Why HTML Works Well for Web Applications

HTML is suitable for web applications because:

- Browsers are built into many computers and portable devices.
- Browser APIs support graphics, animation, audio, video, storage, and other interactive features.
- Efficient use of **HTML and CSS** can reduce dependence on images and improve page-loading performance.
- Semantic markup and appropriate metadata can help search engines understand and index content.
- Applications can provide richer experiences without relying entirely on external plugins.

## Important HTML5 Features

| Feature | Purpose |
|---|---|
| Structural elements | Define the logical organization of a page |
| `<canvas>` and related APIs | Support script-based drawing and graphics |
| `<audio>` and `<video>` | Embed media directly in a page |
| Form input types | Provide specialized controls and browser validation |
| Web Storage APIs | Store application data in the browser |
| Web Workers | Perform intensive background processing without blocking page interactions |
| Drag-and-drop APIs | Support interactive movement of page content |
| Offline capabilities | Allow some application resources or data to remain available without a network connection |

## Form Input Types

HTML5 introduced specialized `type` values for the `<input>` element, including examples such as:

```html
<input type="email">
<input type="number">
<input type="datetime-local">
```

Browsers can provide an appropriate interface and perform basic validation based on the selected type. However, client-side validation must not replace server-side validation because browser-submitted data can be altered or bypass validation entirely.

The transcript refers to `datetime`; modern HTML commonly uses `datetime-local`, and exact browser support should be checked.

## Web Storage

Web Storage APIs allow applications to save key-value data in the browser. Common mechanisms include:

- `localStorage` for data that persists across browser sessions
- `sessionStorage` for data associated with the current tab or session

Storage is useful for preferences and temporary application state, but sensitive information should not be stored there without an appropriate security design.

## Web Workers

A **Web Worker** runs JavaScript separately from the page’s main execution thread. It is useful for processing-intensive tasks that might otherwise make the interface unresponsive.

```text
Main page thread → interface and user interactions
Web Worker       → background computation
```

Workers cannot manipulate the page’s DOM directly. They communicate with the main thread by sending messages.

## Search and Performance

HTML5 can support web visibility and performance through:

- Clear semantic page structure
- Descriptive metadata
- Efficient HTML and CSS
- Reduced use of unnecessary image-based content
- Faster rendering and improved usability

Search-engine behavior varies, so metadata alone does not guarantee better ranking. Meaningful content, semantic structure, accessibility, and overall site quality also matter.
