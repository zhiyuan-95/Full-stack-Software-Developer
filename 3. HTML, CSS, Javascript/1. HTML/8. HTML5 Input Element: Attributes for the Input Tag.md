# Attributes for the HTML `<input>` Tag

HTML5 provides specialized input types and attributes that improve data entry and offer built-in validation. Their appearance and behavior can vary by browser.

## Common Input Types

| Input type | Purpose and behavior |
|---|---|
| `color` | Opens a browser-specific color picker. Unsupported browsers may display a regular text field for a color name or code. |
| `date` | Accepts a year, month, and day without a time zone. The date-picker interface varies by browser. |
| `datetime-local` | Accepts a local date and time without time-zone information. Browsers may provide a calendar and spinner controls. |
| `email` | Appears like a text field but can detect input that does not follow an email-address format. |
| `number` | Accepts numeric input. Supports constraints such as `min`, `max`, and `step`. |
| `range` | Displays a slider between specified minimum and maximum values. JavaScript is needed to display the selected value separately. |
| `search` | Functions similarly to `text`, but its styling and features may differ. Some WebKit-based browsers may provide search history. |
| `tel` | Accepts telephone numbers but does not validate their format by itself. |
| `url` | Checks whether the entered value follows a valid URL format. |

### Telephone-number validation

Telephone numbers may contain characters such as `+`, spaces, parentheses, and hyphens, so `type="tel"` does not restrict input to digits.

Use the `pattern` attribute when a specific format is required:

```html
<input type="tel" pattern="[0-9]{3}-[0-9]{3}-[0-9]{4}">
```

## Additional Input Attributes

### `list` and `<datalist>`

The `list` attribute connects an input field to a `<datalist>`, providing autocomplete suggestions:

```html
<input type="text" list="fruits">

<datalist id="fruits">
  <option value="Apple">
  <option value="Banana">
  <option value="Orange">
</datalist>
```

Unlike `<select>`, a `<datalist>` does not normally restrict the user to its listed options; they are suggestions.

### `placeholder`

The `placeholder` attribute displays a lightly styled example or formatting hint:

```html
<input type="email" placeholder="name@example.com">
```

Placeholder text:

- Disappears when the user enters a value.
- Is not submitted as form data.
- Does not satisfy the `required` attribute.
- Should be treated as a hint rather than a replacement for a field label.

### `required`

The `required` attribute prevents submission until the user provides a value:

```html
<input type="email" required>
```

A field containing only placeholder text is still considered empty.

## Validation Fallback

Not every browser supports every HTML5 input type or validation feature. Possible fallback strategies include:

- Validating fields with JavaScript or libraries such as jQuery.
- Attaching client-side validation to the form’s `submit` event.
- Allowing unsupported controls to behave as ordinary text fields.
- Performing final validation on the server.

Server-side validation remains essential because browser-based validation may be unsupported, bypassed, or manipulated.

## Key Takeaway

HTML5 input types improve usability and provide convenient client-side validation, but their interfaces and support vary across browsers. Use appropriate attributes, provide fallbacks when necessary, and always validate submitted data on the server.
