# CSS Frameworks

## Purpose

A **CSS framework** provides a foundation for building a website’s user interface (UI). It can simplify the creation of:

- Navigation bars
- Forms
- Grid layouts
- Responsive, mobile-friendly pages

Frameworks emphasize different features, so the choice should be based on the project’s need for customization, development speed, consistency, and performance.

## Main approaches

| Approach | How styling works | Main advantage | Main disadvantage |
|---|---|---|---|
| **Vanilla CSS** | You write every style yourself | Complete design control | Requires more time and effort |
| **Utility-first framework** | Single-purpose classes are combined in HTML | Fast development with substantial customization | Verbose HTML and weaker separation of concerns |
| **Component framework** | Pre-styled components and templates are added to the page | Rapid, consistent development with limited CSS knowledge | Restricted to available components and may include unused code |

## Vanilla CSS

**Vanilla CSS** means using CSS without a framework. Developers define every component, state, and layout themselves.

### Advantages

- Complete control over appearance and behavior
- No framework-imposed design limitations
- No unused framework components

### Disadvantages

- Every component must be styled manually
- Maintaining consistent colors, spacing, and typography takes more work
- Development is generally slower

For example, creating a danger link requires separate rules for its normal and hover states.

## Utility-first frameworks

A **utility-first framework** provides small, single-purpose classes that usually represent individual CSS properties. These classes are combined through an element’s HTML `class` attribute.

For example:

```html
<p class="text-center">Centered text</p>
```

Here, `text-center` replaces the need to write `text-align: center;` in a separate stylesheet.

### Advantages

- Styles can be applied directly in HTML
- Faster than writing every CSS declaration manually
- Provides considerable design freedom
- Encourages consistent colors, spacing, typography, and shadows
- Makes responsive styling easier

### Disadvantages

- Many classes can make HTML verbose
- Mixing styling into HTML reduces separation of concerns
- Additional markup may increase page download size and potentially affect performance

## Tailwind CSS

**Tailwind CSS** is a popular utility-first framework. Its classes can be composed directly in HTML to create custom designs.

A danger link, for example, could combine utilities that:

- Underline the text
- Make the text red
- Change it to a darker red when hovered over

### Modifiers

Tailwind uses **modifiers** to apply utilities under particular conditions.

- `hover:` applies a utility while the user hovers over an element.
- `md:` applies a utility at Tailwind’s medium-screen breakpoint, described in the lesson as 768 pixels.
- Large-screen modifiers can apply different styles on larger displays.

A responsive image could therefore have:

- Width `16` (`64px`) by default
- Width `32` (`128px`) on medium screens
- Width `48` (`192px`) on large screens

This allows responsive behavior to be expressed directly in the markup.

## Component frameworks

A **component framework** supplies pre-styled UI components and templates that can be added to a website.

Components may include:

- Buttons
- Links
- Forms
- Navigation elements
- Complete page or website templates

### Advantages

- Websites can be developed rapidly
- Components remain visually consistent
- Less manual styling is necessary
- Only limited CSS knowledge is required for basic use

### Disadvantages

- Customization is limited by what the framework provides
- A needed component may not be available
- The framework may include components and code that the project never uses
- Framework-based websites can develop a similar visual appearance

## Bootstrap

**Bootstrap** is a popular component framework for building responsive websites. It provides individual components as well as templates ranging from sign-in pages to complete websites.

For example, Bootstrap provides a predefined danger-link style:

```html
<a class="link-danger" href="#">Danger link</a>
```

For this particular example, Bootstrap requires less implementation work than Vanilla CSS or Tailwind because the complete style is already provided. However, a component framework is not automatically the easiest choice for every design.

## Choosing an approach

- Choose **Vanilla CSS** when complete control is more important than development speed.
- Choose **Tailwind CSS** when you want fast styling, responsive utilities, and the freedom to compose a custom design.
- Choose **Bootstrap** when rapid development, ready-made components, and visual consistency are the priorities.

## Key takeaway

Utility-first frameworks provide **building blocks for creating your own design**, while component frameworks provide **finished interface elements**. Vanilla CSS offers the most control, Tailwind balances speed with customization, and Bootstrap prioritizes ready-made components and ease of use.
