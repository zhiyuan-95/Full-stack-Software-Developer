# Cloud Storage Types

## Summary

Cloud storage allows data to be stored on provider-managed infrastructure. Some storage must be attached to a compute node before it can be used, while other storage can be accessed directly through the public Internet or a private network connection.

Cloud providers generally manage the underlying storage infrastructure and allow customers to scale capacity as needed. Storage is commonly billed per gigabyte, with faster storage generally costing more.

The four storage types covered are:

1. Direct Attached Storage
2. File Storage
3. Block Storage
4. Object Storage

## Storage comparison

| Storage type | Access method | Main strengths | Main limitations | Typical uses |
|---|---|---|---|---|
| **Direct Attached** | Attached directly to a server | Fast, local access | Usually ephemeral, not shareable, less resilient | Operating system and temporary data |
| **File** | Mounted over a network, commonly through NFS | Shared access and familiar folder hierarchy | Generally slower than direct or block storage | Shared files and directories |
| **Block** | Volume mounted to a compute node | Fast, reliable disk-like storage | Usually attached to one node at a time | Databases and I/O-intensive applications |
| **Object** | Accessed through an API | Highly scalable and economical | Generally higher latency than attached storage | Documents, video, logs, backups, IoT data, binaries, and VM images |

The performance, attachment, and pricing characteristics in this comparison are generalizations from the lecture; exact behavior varies by provider and service tier.

## Direct Attached Storage

**Direct Attached Storage**, also called **Local Storage**, is presented directly to a cloud server. It may be physically located inside the host chassis or within the same rack.

Characteristics:

- Fast access
- Commonly used for the server’s operating system
- Usually tied to a specific compute resource
- Cannot normally be shared with other compute nodes
- Less resilient than other storage options, even when RAID techniques are used

Direct Attached Storage is typically **ephemeral**, meaning its lifetime is tied to the compute resource. If that compute resource is removed, the storage and its data may also be lost.

## File Storage

File storage is commonly presented to compute nodes as **Network File System (NFS)** storage.

NFS storage:

- Connects to compute nodes over an Ethernet network
- Organizes data in a hierarchical folder structure
- Can be mounted by multiple servers simultaneously
- Is familiar to users accustomed to desktop files and folders
- Generally costs less than direct attached or block storage
- Tends to be slower than direct attached or block storage because data travels across a network

File storage is useful when several compute nodes need access to the same files.

## Block Storage

Block storage is provisioned in units called **volumes**. A volume is mounted to a compute node, which sees it as another hard drive.

Characteristics:

- Designed for fast and reliable read/write operations
- Suitable for databases and applications where disk performance is important
- Commonly presented through high-speed storage connections
- Normally mounted to one compute node at a time
- Can be persistent or configured for automatic deletion

Some providers support different connection technologies or multi-attach configurations, so these characteristics are service-dependent.

## IOPS

**IOPS** means **Input/Output Operations Per Second**. It measures how many read or write operations a storage system can perform each second.

IOPS is one indicator of storage performance and is commonly discussed when selecting File or Block Storage.

## Persistent versus ephemeral storage

### Persistent storage

Persistent storage remains available after its attached compute node is terminated.

```text
Compute node terminated
          ↓
Storage and data retained
          ↓
Storage can be attached to another node
```

Customers continue paying for the storage while it exists.

### Ephemeral storage

Ephemeral storage is deleted with the associated compute resource.

```text
Compute node terminated
          ↓
Storage deleted
          ↓
Data lost unless backed up
```

Deleting ephemeral storage stops its associated storage charges, but any unprotected data is lost.

## Snapshots

A **snapshot** represents storage at a particular point in time and can be used to return a volume to an earlier state.

The lecture describes snapshots as:

- Fast to create
- Normally requiring no downtime
- Primarily metadata-based
- Incremental after the first snapshot, recording only subsequent changes
- Suitable for restoring an entire storage volume to a previous state

The lecture states that snapshots do not directly recover individual files. Exact snapshot implementation and file-level recovery options depend on the provider and recovery workflow.

## Object Storage

Object Storage differs from File and Block Storage because it is not mounted to a compute node as a conventional drive. Applications access it through an **API**.

Characteristics:

- Effectively unlimited capacity from the user’s perspective
- No fixed volume size that gradually fills
- Usage-based billing
- Generally inexpensive per unit of storage
- Generally slower than attached storage for read/write operations
- Well suited to large quantities of unstructured data

Common uses include:

- Documents
- Images and video
- Logs
- Backups
- Internet of Things (**IoT**) data
- Application binaries
- Virtual machine images

“Cheapest,” “slowest,” and “infinite” are simplified lecture descriptions. Actual price, performance, quotas, and scalability depend on the provider, storage class, request pattern, and network connection.

## Choosing a storage type

| Requirement | Likely storage choice |
|---|---|
| Fast temporary storage tied to one server | Direct Attached Storage |
| Shared folders used by several servers | File Storage |
| High-performance storage for a database | Block Storage |
| Large-scale unstructured data accessed through APIs | Object Storage |
| Data that must survive compute-node deletion | Persistent File or Block Storage |
| Temporary data that may be discarded with the server | Ephemeral Storage |

## Key takeaway

Cloud storage should be selected according to how applications access data, whether several servers must share it, the required speed and durability, and whether the data must survive compute-resource termination. Direct Attached Storage prioritizes local speed, File Storage supports shared hierarchical access, Block Storage provides high-performance volumes, and Object Storage provides scalable API-based storage for unstructured data.
