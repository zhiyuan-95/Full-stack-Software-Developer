# Object Storage Tiers, APIs, and Backup

## Summary

Object Storage services organize data into storage **tiers** or **classes** based largely on how frequently objects are accessed. Frequently accessed data generally has a higher storage price but faster retrieval, while archival data costs less to store but may have higher retrieval charges and longer retrieval times.

Object Storage is accessed through an API rather than mounted to a compute node. Many providers support APIs compatible with the **Amazon S3 API**, allowing applications to interact with different providers through similar operations.

## Storage tiers

| Tier | Typical access frequency in the lecture | Storage cost | Retrieval characteristics |
|---|---|---|---|
| **Standard** | Frequent access | Highest per-gigabyte storage cost | Intended for immediate or regular access |
| **Vault or Archive** | Once or twice a month—or less | Lower storage cost | Retrieval may cost more or take longer |
| **Cold Vault** | Once or twice a year | Lowest storage cost | Retrieval may take hours if data is offline |

Tier names, access expectations, prices, and retrieval times vary by provider.

### Cost-performance tradeoff

```text
Frequent access                                      Rare access
     │                                                     │
Standard ─────────→ Vault/Archive ─────────→ Cold Vault
     │                                                     │
Higher storage cost                              Lower storage cost
Faster retrieval                                 Slower retrieval
Lower access penalty                         Higher retrieval charges
```

The lecture states that Cold Vault storage may cost a fraction of a US cent per gigabyte per month. This is a provider-specific, time-sensitive pricing claim.

## Automatic archiving

Providers may support lifecycle or automatic-archiving rules that move objects into less expensive tiers after a defined period.

```text
Object uploaded
      ↓
Standard tier
      ↓  lifecycle condition met
Archive tier
      ↓  longer archival condition met
Cold tier
```

The rule may evaluate object metadata, such as object age or access-related information, to decide when a transition should occur. The available conditions differ by provider.

Automatic tiering helps reduce storage cost without requiring every object to be moved manually.

## Performance considerations

Traditional Object Storage does not normally provide user-selected **IOPS** options like File or Block Storage.

Its performance model is based on API requests rather than mounted-disk operations. It is therefore not intended to behave like a low-latency local disk.

Performance depends on:

- Storage tier
- Object size
- Network connection
- Provider implementation
- Retrieval state
- Request volume

The lecture characterizes Object Storage as slow compared with File and Block Storage, with downloads taking seconds or longer. That is a simplified comparison: standard-tier response times vary, while offline archival tiers may genuinely require minutes or hours to restore data.

If an application requires consistently low-latency file access, File or Block Storage may be more appropriate.

## Pricing model

Object Storage charges may include:

- Storage consumed per gigabyte per month
- API or access requests
- Data retrieval
- Archive restoration
- Tier-specific charges

Archive and Cold Vault tiers generally reduce the monthly storage price but may increase retrieval charges.

The correct tier therefore depends on the complete access pattern:

| Access pattern | Likely tier |
|---|---|
| Data used regularly | Standard |
| Data retrieved occasionally | Vault or Archive |
| Long-term records retrieved rarely | Cold Vault |

Selecting a cheap archival tier for frequently accessed data may increase total cost because of repeated retrieval charges.

## Object Storage APIs

Object Storage is accessed through an **Application Programming Interface (API)**.

Applications can use API calls to:

- Create and manage buckets
- Upload objects
- Download objects
- List objects
- Retrieve metadata
- Delete objects
- Manage storage configuration

### S3-compatible APIs

The lecture identifies the **S3 API**, based on Amazon Web Services’ Amazon S3 service, as the most common Object Storage API model.

Many providers offer **S3-compatible APIs**. This can make application code more portable across vendors because similar HTTP requests and operations are available.

S3 compatibility should not be assumed to mean perfect interchangeability. Authentication, supported features, limits, and provider-specific behavior may differ.

### RESTful access

The API is HTTP-based and follows a REST-style model.

Common object operations include:

```text
PUT    → Upload or replace an object
GET    → Download an object
DELETE → Remove an object
```

Bucket-management operations are also available through the API.

## Backup and disaster recovery

Object Storage can support **backup and disaster recovery (DR)** for new and existing applications.

Many backup products can send backup data directly to cloud Object Storage.

The lecture presents this as an alternative to off-site tape storage:

| Tape-based backup | Object Storage backup |
|---|---|
| Physical tapes must be loaded and removed | Backups are transferred through software and APIs |
| Tapes must be transported off-site | Geographic redundancy can be provided by the cloud service |
| Restores require locating and loading media | Data can be requested through the storage service |
| Physical media handling is required | Provider manages the underlying storage infrastructure |

Potential benefits include:

- Less physical media handling
- Automated off-site storage
- Geographic redundancy
- Integration with backup software
- Potentially faster restoration than retrieving and loading off-site tapes

The suitability and recovery time still depend on the storage tier, network capacity, backup design, and recovery requirements. Cold archival tiers may delay restoration.

## Key takeaway

Object Storage tiers exchange storage cost for retrieval speed and access cost. Standard tiers suit frequently accessed objects, while Archive and Cold Vault tiers suit progressively less-frequent access. Lifecycle rules can automatically move aging data into cheaper tiers. S3-compatible REST APIs make Object Storage accessible to applications and useful for scalable backup and disaster recovery, but provider differences, retrieval delays, and access charges must be considered.

> **Source note:** Pricing, tier names, retrieval times, and performance statements are provider-dependent lecture claims and were not independently verified as current.
