# Object Storage

## Summary

**Object Storage** stores data as objects inside containers called **buckets**. Unlike File or Block Storage, it is not mounted to a particular compute node. Applications and authorized clients upload, download, and manage objects through an **Application Programming Interface (API)**.

Object Storage is designed for large amounts of unstructured data, elastic capacity, and relatively low storage cost. It is best suited to data that is written and then read as a complete object rather than constantly modified in place.

## Access model

```text
Application or client
        │
        │ API request
        ↓
Object Storage service
        └── Bucket
            ├── Object A
            ├── Object B
            └── Object C
```

A dedicated compute attachment is not required. Anything capable of making an authorized API request can interact with the service, although the calling application or client still runs on some computing device or service.

Common API operations include:

- Uploading objects
- Downloading objects
- Listing objects
- Retrieving metadata
- Deleting objects
- Managing buckets

## Buckets and objects

A **bucket** is a logical container for objects. It resembles a folder because it can have a meaningful name and can group related data, but the underlying storage model is flat.

Key characteristics:

- A bucket holds objects.
- Multiple buckets can exist in one storage account or service instance.
- A bucket cannot be placed inside another bucket.
- No fixed bucket size must be provisioned in advance.
- Capacity grows or shrinks as objects are added or removed.
- Providers may display object-name prefixes like folders, but the underlying model remains object-based rather than a traditional directory hierarchy.

## Object metadata

Each object includes metadata—data describing the stored object.

Examples from the lecture include:

- Object ID
- Storage time
- Last-accessed time
- Information applications can use to locate and retrieve the object

Metadata helps applications identify, manage, search for, and access stored data. The exact metadata available depends on the provider.

## Capacity and billing

With File or Block Storage, customers commonly provision a volume with a specified capacity, such as a number of gigabytes or terabytes.

Object Storage works differently:

- No fixed bucket capacity is normally selected.
- Customers add objects as needed.
- Charges are based primarily on actual storage consumption.
- The provider supplies the underlying capacity.
- A bucket may grow from a few bytes to multiple petabytes, subject to provider limits.

The lecture describes Object Storage as **effectively infinite** from the user’s perspective. This means highly elastic and provider-managed rather than literally unlimited.

### Pricing

The lecture states that storage may cost a couple of US cents per gigabyte per month—or less for some tiers. This is a time-sensitive, provider-specific claim.

Actual cost may include:

- Stored data
- API operations
- Data retrieval
- Network transfer
- Replication or resilience level
- Storage tier
- Access frequency

## Resilience and availability

The provider manages the underlying capacity, resilience, and availability. Different bucket configurations may offer different protection levels.

### Single-location resilience

Data may be stored redundantly within one Data Center.

Potential advantages:

- Geographic data residency
- Lower cost
- Suitable when cross-location availability is unnecessary

Limitation:

- Less protection from a complete Data Center outage

### Multi-zone or multi-region resilience

Data may be replicated across:

- Multiple Data Centers
- Multiple Availability Zones in one Region
- Multiple Regions

These options generally cost more but provide greater resilience and availability.

## Suitable data

Object Storage is well suited to large quantities of unstructured or relatively static data, including:

- Text files and documents
- Audio and video
- Images
- Internet of Things (**IoT**) data
- Application binaries
- Virtual machine images
- Logs
- Backups
- Data archives

It is especially useful when:

- Data volume changes unpredictably.
- Applications can access data through APIs.
- Shared access is required without mounting a disk.
- Low per-gigabyte cost is important.
- Consistently fast read/write latency is unnecessary.

## Unsuitable workloads

The lecture identifies Object Storage as unsuitable for directly running:

- Operating systems
- Transactional databases
- Applications requiring mounted disks
- Workloads requiring frequent in-place file changes
- Workloads requiring consistently low-latency reads and writes

Object Storage normally treats an object as a complete unit. Changing its contents commonly involves replacing the object rather than editing blocks within it.

## Object, File, and Block comparison

| Characteristic | Object Storage | File Storage | Block Storage |
|---|---|---|---|
| Access | API | Mounted file system | Mounted volume |
| Organization | Buckets and objects | Folders and files | Addressed blocks |
| Structure | Flat | Hierarchical | Raw block structure |
| Capacity | Expands with usage | Provisioned capacity | Provisioned capacity |
| Compute attachment | Not required | Required | Required |
| Sharing | Accessible to authorized API clients | Commonly shared by multiple nodes | Normally attached to one node |
| Performance | Generally higher latency | Moderate and network-dependent | Consistent, low-latency performance |
| Typical data | Static, unstructured content | Shared files | Databases and high-IOPS workloads |
| Typical cost | Generally lowest per stored GB | Moderate | Generally highest |

These are general distinctions; actual performance and pricing depend on the provider and service tier.

## Storage tiers

Providers may offer different bucket or storage tiers based on:

- Resilience and geographic replication
- Availability requirements
- Frequency of object access
- Retrieval expectations

Frequently accessed data may use a different tier from archives that are rarely retrieved. Each tier can have different storage, access, and retrieval charges.

## Key takeaway

Object Storage provides API-based, elastic storage for large quantities of unstructured data. Objects are stored in flat buckets, include descriptive metadata, and do not require a mounted compute volume. It is ideal for documents, media, backups, logs, IoT data, VM images, and archives, but not for operating systems, databases, or other workloads requiring continuously changing, low-latency disk storage.
