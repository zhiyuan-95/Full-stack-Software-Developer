# Cloud Computing Security

## Overview

Digital transformation is driving organizations to replace or extend traditional infrastructure with cloud-based tools and services. Cloud computing reduces time-consuming IT work, but insecure adoption can expose organizations to external threats, data breaches, financial loss, and reputational damage.

Effective cloud adoption therefore requires:

- Security controls across public, private, and hybrid clouds
- Visibility into data movement and access
- Regulatory compliance and appropriate approvals
- Clear responsibility between the organization and cloud provider
- Countermeasures against modern cyberattacks

## Cloud Service Models

Cloud providers offer three primary **as-a-service** models:

- **Infrastructure as a Service (IaaS):** Provides infrastructure such as servers, storage, and networking.
- **Platform as a Service (PaaS):** Provides a managed platform for developing and running applications.
- **Software as a Service (SaaS):** Delivers complete applications to users.

Although providers secure their infrastructure and services, customers retain responsibility for protecting certain data, identities, configurations, applications, and access credentials. The exact division depends on the service model.

## Major Cloud-Security Challenges

### 1. Lack of visibility

In public-cloud environments, organizations may struggle to determine:

- Who is accessing their data
- Which services employees are using
- How data moves across cloud environments
- Whether cloud resources are being used outside approved organizational processes

Limited visibility makes detecting unauthorized activity and maintaining compliance more difficult.

### 2. Multitenancy

Public-cloud providers may host infrastructure and services for multiple customers on shared physical systems. Strong tenant isolation is therefore essential. A weakness in the provider’s platform could potentially affect customers beyond the organization initially targeted.

### 3. Access management and shadow IT

Cloud resources can be accessed from many devices and geographic locations. Organizations must control:

- User identities and permissions
- Device and location-based access
- Unauthorized cloud services, known as **shadow IT**
- Former employees, contractors, and partners who no longer require access

### 4. Misconfiguration

Incorrect cloud configurations are a major source of exposed records. Examples include:

- Inappropriate privacy or sharing settings
- Excessive access permissions
- Publicly accessible data assets
- Default administrative passwords

## Evolving Threats and Risks

### Insider threats

Insider threats can involve current or former employees, contractors, business partners, or anyone with previous access to organizational systems.

Authorized access can be abused to view, modify, disclose, or destroy information. Because this activity may appear legitimate to perimeter-based security systems, insider threats can be difficult to detect.

### Distributed denial-of-service attacks

A **distributed denial-of-service (DDoS)** attack overwhelms a server or service with traffic generated by multiple synchronized systems. The goal is to exhaust resources and make the service unavailable.

The lecture specifically mentions **Simple Network Management Protocol (SNMP)**, which is used by devices such as routers, switches, modems, printers, and servers. More precisely, vulnerable SNMP services can be exploited for traffic amplification, but DDoS attacks can also use many other protocols and techniques.

### Data breaches

A data breach occurs when unauthorized users gain access to sensitive information. It may result from:

- Weak security controls
- Misconfigured resources
- Compromised credentials
- Excessive permissions
- Malicious insiders

Consequences can include financial costs, regulatory penalties, operational disruption, and reputational damage.

## Shared-Responsibility Model

The **shared-responsibility model** divides cloud-security duties between the cloud provider and the customer. The provider generally protects the underlying cloud, while the customer protects what it deploys, configures, stores, and accesses within that cloud.

| Service model | Provider responsibilities | Customer responsibilities |
|---|---|---|
| **IaaS** | Physical data centers, hardware, networking, and underlying infrastructure | Operating system, applications, software configuration, identities, access, and data |
| **PaaS** | Infrastructure, platform, runtime, and operating system | Application code, application configuration, identities, access, and data |
| **SaaS** | Infrastructure and the managed service application | Login credentials, user access, sharing settings, configuration, and appropriate handling of organizational data |

As services move from **IaaS → PaaS → SaaS**, the provider manages more of the technology stack. However, customers never surrender all responsibility—especially for identity management, credentials, permissions, configuration, and proper data use.

## Key Takeaway

Cloud providers secure the underlying services, but organizations remain accountable for using those services securely. Successful cloud adoption depends on visibility, access control, secure configuration, compliance, threat monitoring, and a precise understanding of the shared-responsibility model.
