# Hybrid Cloud Security

## Overview

Moving workloads into a **hybrid cloud environment** expands an organization’s attack surface and introduces new data-security and compliance challenges. Organizations therefore need a **data-centric cybersecurity program** with centralized visibility and monitoring across on-premises and cloud environments.

Cloud security maturity must develop across three areas:

- **People:** Clearly defined responsibilities and secure behavior
- **Processes:** Governance, policies, metrics, and continuous monitoring
- **Technology:** Security tools that protect data, identities, networks, and cloud resources

## Data-Security Capabilities

A strong data-security program should:

1. **Identify critical data**
   - Determine which data assets are most important.
   - Identify who can access them.
   - Understand how they are currently protected.

2. **Prevent data loss**
   - Detect policy violations.
   - Block or correct prohibited actions.
   - Reduce accidental exposure, deletion, or sharing.

3. **Establish data-security governance**
   - Define security processes and metrics.
   - Continuously discover and classify data.
   - Maintain security as an ongoing, steady-state activity.

4. **Monitor database security**
   - Apply data-protection and compliance policies consistently.
   - Monitor databases across the entire hybrid-cloud environment.

## Identity and Access Management

**Cloud identity and access management (IAM)** controls who can access cloud resources and under what conditions. An effective IAM strategy should support **zero-trust architecture**, risk-based protection, and repeated verification of access requests.

### IBM Cloud considerations described in the lecture

Organizations should:

- Modernize at a pace that matches business requirements.
- Preserve useful investments and on-premises applications.
- Gradually introduce an appropriate cloud IAM architecture.
- Complement or replace existing access-control frameworks as needed.
- Scale IAM to support millions of users or transactions without major infrastructure changes.

### Zero trust

The **zero-trust model** does not automatically trust a user or device because it is inside the organizational network. Access should connect:

> The right users to the right data, at the right time, under the right conditions.

A zero-trust implementation can provide:

- Centralized access control
- Protection of client confidentiality
- Reduced insider risk
- Security for remote resources
- Contextual verification based on identity, device, location, and risk

## Cloud Network Security

**Cloud network security** includes the technologies, policies, controls, and processes used to protect data and traffic across public, private, and hybrid-cloud networks.

Because extending a network into the cloud introduces new security implications, organizations should deploy security controls designed to operate directly within cloud environments.

### Benefits

- Centralized security monitoring and management
- Easier creation and updating of granular policies
- Real-time intrusion detection and prevention
- Protection against **distributed denial-of-service (DDoS)** and other web-based attacks
- Automated configuration and management
- Reduced risk of misconfiguration
- Greater control over network traffic
- Encryption of data **at rest** and **in transit**
- Centralized identity and access protection

## Three-Phase Cloud-Security Approach

### Phase 1: Identify usage and risk

Organizations should establish visibility before applying controls:

- Determine how data is accessed.
- Detect unknown or unauthorized cloud usage.
- Check cloud-service configurations.
- Monitor for malicious use of cloud data.

### Phase 2: Protect cloud systems

After identifying risk, organizations should:

- Assign appropriate protection policies.
- Encrypt sensitive data.
- Define policies for data sharing.
- Restrict sharing with unknown devices.
- Implement bot-protection and mitigation tools.
- Use suitable anti-malware solutions.

### Phase 3: Respond to attacks

When suspicious or high-risk activity occurs:

- Add authentication and verification steps for high-risk access.
- Create or update policies as new cloud services are adopted.
- Adapt controls based on newly observed attack methods.

## NIST Cybersecurity Framework

The lecture presents five NIST cybersecurity functions:

1. **Identify:** Understand assets, systems, data, and risks.
2. **Protect:** Apply safeguards that reduce security risk.
3. **Detect:** Discover attacks and abnormal activity.
4. **Respond:** Contain and manage cybersecurity incidents.
5. **Recover:** Restore systems and improve resilience after an incident.

These functions establish a repeatable security lifecycle rather than treating security as a one-time implementation.

## Cloud Security Posture Management

**Cloud security posture management (CSPM)** continuously evaluates cloud environments for security weaknesses, especially **misconfigurations**.

CSPM supports several core security capabilities:

- Identity and access management
- Regulatory compliance management
- Traffic monitoring
- Threat response
- Risk mitigation
- Digital-asset management

Its main purpose is to identify configuration drift and policy violations before attackers can exploit them.

## Emerging Cloud-Security Trends

As cloud adoption grows, cloud environments become more attractive targets for cybercriminals. Major trends identified in the lecture include:

- Multi-cloud security strategies
- **Cybersecurity mesh**
- Zero-trust security models
- Hybrid and multi-cloud environments
- Cloud-native tools and applications
- **DevSecOps**
- Security for remote workforces
- Artificial intelligence and machine learning for threat detection
- Increased focus on privacy and data-protection regulations

## Key Takeaway

Hybrid-cloud security requires coordinated protection of **data, identities, networks, configurations, and workloads**. Organizations should first identify their assets and risks, then implement preventive controls, continuously detect suspicious activity, respond to incidents, and prepare for recovery. Centralized monitoring, zero-trust IAM, CSPM, encryption, and strong governance provide the foundation for this security lifecycle.
