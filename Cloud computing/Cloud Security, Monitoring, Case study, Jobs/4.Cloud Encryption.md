# Cloud Encryption

## Role in Cloud Security

Encryption is often described as the **last line of defense** in a layered security model, particularly for public-cloud environments. If unauthorized parties access or intercept encrypted data, it should remain unreadable without the correct key.

A broader cloud data-protection system may also provide:

- Data access control
- Encryption-key management
- Certificate management

Encryption reduces exposure but does **not eliminate security risk**. It shifts much of that risk from the data to the encryption keys.

## How Encryption Works

Encryption scrambles readable data—**plaintext**—into an illegible form called **ciphertext**.

The lecture identifies two central components:

- **Encryption algorithm:** Defines how data is transformed into an unreadable form.
- **Decryption key:** Enables authorized parties to restore the encrypted data to a readable form.

Cloud providers may offer:

- Selective encryption of data classified as sensitive
- Broader encryption covering all data uploaded to the cloud

Keys must be protected carefully. If the required key is lost and no valid recovery method exists, the encrypted data may become permanently unreadable.

## Three States of Data Protection

| Data state | Meaning | Primary protection |
|---|---|---|
| **At rest** | Data stored in databases, disks, or other storage systems | Storage and database encryption |
| **In transit** | Data moving between locations, systems, or services | Secure transport protocols and endpoint authentication |
| **In use** | Data being processed in memory | Specialized techniques that protect data during computation |

### Encryption at Rest

Encryption at rest protects physically stored data. Available options depend on application and business requirements and may include:

- Block-storage encryption
- File-storage encryption
- Built-in object-storage encryption
- Database encryption services

### Encryption in Transit

Encryption in transit protects data moving between locations. The process includes:

1. Encrypting data before transmission.
2. Authenticating the communicating endpoints.
3. Decrypting and verifying the data upon arrival.

**Secure Sockets Layer (SSL)** and **Transport Layer Security (TLS)** are named as common protocols. They may protect:

- Connections to websites
- Traffic between servers
- Communication among cloud services

> SSL is now a legacy protocol; modern systems generally use TLS.

### Encryption in Use

Encryption in use protects data while it is being processed in memory. Certain specialized technologies allow computations to be performed on protected or encrypted data without exposing its plaintext.

> This capability requires specific techniques and is not provided by every encryption system.

## Server-Side and Client-Side Encryption

### Server-Side Encryption

Server-side encryption occurs after cloud storage receives the data but before writing it to disk.

The lecture describes two key-management approaches:

- **Customer-supplied encryption keys:** The customer creates and manages the keys.
- **Customer-managed encryption keys:** The customer manages keys through the cloud provider’s key management service.

Because encryption happens within the cloud service, the provider participates in the encryption workflow.

### Client-Side Encryption

Client-side encryption occurs before data is sent to cloud storage.

The customer controls the encryption algorithm and keys, which are not exposed to the cloud provider. If implemented correctly and the provider never receives the keys, the provider should be unable to decrypt the hosted data.

## Multi-Cloud Data Protection

Enterprises operating across **on-premises, hybrid-cloud, and multi-cloud environments** benefit from a unified data-protection strategy.

Multi-cloud encryption services may combine:

- Data-access management
- Integrated key management
- Encryption across distributed workloads
- Centralized access policies
- Aggregated access logs

A multi-cloud encryption console may allow administrators to:

- Define and manage access policies.
- Create, rotate, and manage encryption keys.
- Consolidate access logs across environments.

The goal is consistent protection for sensitive workloads regardless of where the data resides.

## Encryption-Key Management

Because encrypted data depends on its keys, compromising a key may undermine the encryption itself. Effective key management must cover the key’s complete lifecycle, including:

1. Creation
2. Secure storage
3. Distribution and authorized use
4. Rotation
5. Backup and recovery
6. Revocation or destruction

Cloud **Key Management Services (KMS)** can help customers manage keys used by cloud services and customer-built applications.

Depending on the service configuration, keeping keys under customer control can help protect data from unauthorized users and limit the cloud provider’s ability to access it.

## Key-Management Best Practices

- Store encryption keys separately from encrypted data.
- Keep key backups off-site and audit them regularly.
- Rotate or refresh keys periodically.
- Require multifactor authentication for both master and recovery keys.
- Limit key access according to roles and operational needs.
- Maintain recovery procedures so that losing one key does not make critical data permanently inaccessible.

## Key Takeaway

Cloud encryption must protect data **at rest, in transit, and in use**, but its effectiveness ultimately depends on secure key management. Encryption algorithms protect the data; carefully controlled, recoverable, and regularly rotated keys preserve that protection throughout the data lifecycle.
