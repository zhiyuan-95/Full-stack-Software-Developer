# Identity and Access Management (IAM) in Cloud Security

## Why IAM Matters

According to the **Cloud Security Report by Cybersecurity Insiders**:

- **Data loss and leakage** is cybersecurity professionals’ top cloud security concern.
- The largest perceived vulnerability is **unauthorized access** caused by compromised employee credentials or improper access controls.
- **Insecure interfaces and APIs** are another major vulnerability.

**Identity and Access Management (IAM)**—also called **access control**—acts as the cloud’s first line of defense. It authenticates users, authorizes permitted actions, and provides user-specific access to cloud resources, services, and applications.

A comprehensive IAM strategy must support:

- Organizational users
- Internet and social-identity users
- Third-party business partners
- Vendors

## Main Types of Cloud Users

### 1. Administrative Users

Cloud platform administrators, operators, and managers typically:

- Create, update, and delete application or service instances.
- Monitor team members’ activities.
- Have extensive access to cloud environments.

A compromised administrative account could allow an attacker to:

- Steal data from production databases.
- Deploy malicious applications within the customer’s domain.
- Deface or destroy existing applications.

### 2. Developer Users

This category includes cloud application developers, platform developers, and application publishers. They may be authorized to:

- Read sensitive information.
- Create, update, and delete applications.

Because of these permissions, compromised developer accounts also present significant security risks.

### 3. Application Users

Application users are the people who use cloud-hosted applications. Their identities and permissions must be managed at the application level.

## Core IAM Components

### Authentication and Identity Services

Authentication verifies a user’s identity before granting access. Cloud applications can authenticate users through several identity providers:

- Cloud directories
- Social identity providers such as **Google, LinkedIn, Facebook, and Twitter**
- Enterprise-hosted identity providers
- Cloud-hosted identity providers

Applications may also use **API keys** or other unique identifiers to identify a calling application or user.

### Multifactor Authentication

**Multifactor authentication (MFA)** reduces identity-theft risk by requiring an additional form of verification, such as:

- Single-use passwords or PINs
- Certificates
- Security tokens
- Time-based one-time passwords
- Risk-based authentication

Risk-based authentication can evaluate contextual information such as changes in a user’s location, previous activity, and preferences.

### Cloud Directory Services

Cloud directory services securely manage:

- User profiles
- Credentials
- Password policies

A centralized cloud directory means individual cloud-hosted applications do not need to maintain separate user repositories.

### Reporting

IAM reporting can provide either:

- A **user-centric view** showing the resources available to a user, or
- A **resource-centric view** showing which users can access a resource.

Reports can identify:

- Which users have access to particular resources
- Changes in access rights
- The access being exercised by each user
- The conditions under which access occurs

### Auditing and Compliance

Auditing is essential for both cloud providers and cloud consumers. Auditors use IAM records and processes to:

- Validate implemented controls against organizational security policies.
- Assess compliance with industry and risk requirements.
- Identify and report deviations.

### User and Service Access Management

This capability allows application and service owners to provision and de-provision customer, partner, and vendor profiles with minimal human intervention. Access can be based on the user’s:

- Role
- Organization
- Applicable access policies

## Protecting Privileged Accounts

Administrative and developer accounts require tight control throughout their entire lifecycle because they can access sensitive information.

Important safeguards include:

- Assigning roles on specific resources during user provisioning
- Enforcing password requirements, including minimum length and special characters
- Requiring MFA, such as time-based one-time passwords
- Immediately removing or adjusting access when users leave the organization or change roles

## Access Groups and Policies

Cloud IAM services commonly allow administrators to:

- Create access groups
- Add users to those groups
- Manage access for existing users

An **access group** contains users and service IDs that need the same permissions. One or more access policies can then be assigned to the entire group.

Each **access policy** contains three main elements:

| Element | Purpose |
|---|---|
| **Subject** | The users, service IDs, or access groups receiving permission |
| **Target** | The resource or provisioned service offering being accessed |
| **Role** | The actions the subject is permitted to perform on the target |

Access groups streamline permission assignment, avoid repeatedly configuring individual users, and reduce the total number of policies required within an account.

## Key Takeaway

IAM secures cloud environments by controlling **who or what can access a resource and which actions they can perform**. Effective IAM combines authentication, MFA, centralized directories, role-based provisioning, reporting, auditing, access groups, and prompt de-provisioning—especially for high-privilege administrative and developer accounts.
